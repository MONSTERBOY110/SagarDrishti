# ADR-0002 - Python 3.11 for the data plane (TRD specifies 3.12)

**Date:** 2026-09-07 · **Status:** accepted · **Owner:** lead

## Context

TRD §2 specifies FastAPI on Python 3.12. The build machine has 3.14 as its
default interpreter and 3.11 also installed. Python 3.14 is too new for parts of
the scientific stack to have reliable Windows wheels, and compiling `netCDF4`
from source on Windows is exactly the class of problem we are trying not to have
at 3 a.m. in a finale.

Observed during setup: `zarr==2.18.3` is **incompatible with
`numcodecs>=0.16`** - 0.16 removed `numcodecs.blosc.cbuffer_sizes`, which zarr 2
imports at module load. This is a genuine breakage, not a pinning nicety.

## Decision

- Use **Python 3.11** (`py -3.11 -m venv .venv`) for `services/api`,
  `services/agent` and `tools/`, and pin CI to 3.11.
- Pin **`numcodecs==0.13.1`** alongside `zarr==2.18.3` rather than moving to
  zarr 3.x. Zarr 2 is the well-trodden path, xarray supports it completely, and
  the on-disk format is readable by every tool we might reach for in the finale.

Verified on 3.11.9: numpy 2.2.1, xarray 2025.1.1, netCDF4 1.7.2, zarr 2.18.3,
dask 2024.12.1, cf-xarray 0.10.0, gsw 3.6.19, pyarrow 18.1.0, matplotlib 3.10.0 - plus a zarr write/read roundtrip.

## Consequences

- A one-line change (the venv command plus CI's `python-version`) moves us to
  3.12 if we ever need to. Nothing in the code depends on 3.11 behaviour.
- TRD §2 now differs from reality by one minor version. This ADR is the record;
  the TRD is deliberately not edited, because it is a design document we may
  show to judges and quiet edits to shown documents are how teams lose track of
  what was claimed.
